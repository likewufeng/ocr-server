# 银行卡专用区域定位改造说明

## 目标

对显式传入 `document_type=bank_card` 的请求，首轮结构化解析后卡号或有效期为空时，使用银行卡专用检测模型定位 `card_number`、`date` 区域，裁剪后再调用现有 PP-OCR，最后仍由现有 `BankCardParser` 完成 Luhn 校验、IIN 匹配、银行名称和卡类型解析。

该功能不会改变身份证、营业执照、发票的推理路径。

## 为什么不直接接入原项目的 Python 代码

`CreditCard-OCR` 的完整方案是 YOLOv8 定位后调用 CRNN。当前服务使用 PaddleOCR v6，并且 CPU 生产镜像没有 PyTorch、Ultralytics 依赖。

本项目只参考其可靠的“先定位、再识别”思路：

```text
银行卡原图 -> ONNX YOLO 区域定位 -> 裁剪卡号/有效期 -> PP-OCR v6 -> 现有字段解析和校验
```

运行时通过 OpenCV DNN 加载 ONNX，不引入 PyTorch 或 Ultralytics，保持 Docker 镜像体积和 CPU 资源可控。

## 模型导出

首次使用前，在开发机导出已下载项目的模型。此步骤只在开发机安装临时依赖，生产镜像和 `requirements.txt` 不需要增加这些依赖：

```powershell
.\scripts\run_bank_card_roi_export.ps1
```

脚本会在 `.tools/onnx-export-venv` 创建仅供导出的隔离环境，复制原始 `.pt` 权重到项目临时构建目录，导出并使用 `onnxslim` 简化图，最后执行独立 `test` 集评测。这个简化步骤是必须的：当前 OpenCV DNN 无法加载未简化图中的 `Floor` 节点。生产运行仍只需要 OpenCV DNN，不需要安装 PyTorch、Ultralytics、ONNX 或 onnxslim。

导出成功后应存在：

```text
models/bank_card_roi/yolo_best.onnx
```

不要复制原仓库的训练图片、CRNN 权重或训练代码进生产镜像。使用公开数据训练、发布或再分发前，需要确认其上游授权范围。

## 先验证定位模型

先在原仓库的独立 `test` 集计算区域定位召回率：

```powershell
.\.tools\onnx-export-venv\Scripts\python.exe scripts\evaluate_bank_card_roi_detection.py `
  --model models\bank_card_roi\yolo_best.onnx `
  --dataset 'D:\web\self\study\dataset\CreditCard-OCR\dataset for detection\detection' `
  --split test `
  --output reports\bank_card_roi_test
```

输出 `reports/bank_card_roi_test.md` 和 CSV 明细。`card_number`、`date` 的 IoU 0.5 召回率应分别达到至少 95% 后，再进行接口 A/B。该评测只衡量检测框位置，不表示卡号文本识别率。

## 启用与回退

`.env` 默认：

```dotenv
OCR_BANK_CARD_ROI_ENABLED=false
```

验证通过后改为：

```dotenv
OCR_BANK_CARD_ROI_ENABLED=true
OCR_BANK_CARD_ROI_MODEL_FILE=models/bank_card_roi/yolo_best.onnx
```

重启 `python start.py` 或重建 Docker 容器后生效。为避免复用旧 OCR 缓存，同时把 `OCR_CACHE_VERSION` 加 1。

模型文件不存在、读取失败或局部 OCR 异常时，服务会记录告警并回退到原有整图 OCR，不会使 `/ocr` 失败。每次触发区域补识别后，`data/outputs/{request_id}/` 中会保存：

- `bank_card_roi_recovery.json`：检测框、触发原因和补识别行数。
- `bank_card_card_number_roi_*.jpg`：实际参与局部 OCR 的卡号裁剪图。
- `bank_card_date_roi_*.jpg`：实际参与局部 OCR 的有效期裁剪图。

## 性能约束

区域模型只在 `document_type=bank_card` 且首轮缺少卡号或有效期时运行。正常识别完整的银行卡不会增加检测或二次 OCR。

触发时会额外增加一次 ONNX 检测和 1 至 3 个局部 OCR 调用，CPU 环境的实际 P95 必须用本地银行卡金标集进行 A/B 后决定是否上线。不要在未压测的情况下直接用于 CPU 高并发生产环境。
