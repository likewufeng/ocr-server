# 银行卡识别数据维护

## 数据职责

银行卡的结构化解析分为三层：

1. 卡面 OCR 文本：识别银行名称、借记卡或信用卡文案、有效期。
2. 银行别名目录：把中文简称、英文名称和 OCR 常见写法标准化为银行全称。
3. BIN/IIN 目录：当 logo 或银行名称漏识别时，按 6 位或 8 位号段补充银行和卡种。
4. 凸印卡号修复：单个字符被识别为 `~`、`*` 等符号时，只有替换后通过 Luhn 校验的候选才会被采用。

卡种返回固定为 `借记卡`、`信用卡` 或空字符串。空字符串表示没有足够依据，服务不会仅凭卡号长度猜测卡种。

接口会额外返回以下诊断字段：

| 字段 | 说明 |
| --- | --- |
| `bank_name_source` | `ocr_alias`、`ocr_generic`、`bin` 或 `unknown` |
| `bank_name_confidence` | OCR 置信度或 BIN 匹配置信度 |
| `card_type_source` | `card_face`、`bin` 或 `unknown` |
| `card_type_confidence` | OCR 置信度或 BIN 匹配置信度 |

## 数据文件

内置文件为 `app/resources/bank_card/catalog.json`，包含：

- `banks`：标准银行名及中英文别名。
- `card_type_aliases`：卡面产品名、中文和英文卡种文案。
- `bin_rules`：经过验证的 6 位或 8 位 BIN/IIN 规则。

补充 IIN 数据文件为 `app/resources/bank_card/iin_catalog.json`。人工维护的
`bin_rules` 优先于补充 IIN 数据，避免公开数据覆盖已经按业务样本校验过的规则。

每条 BIN 规则格式如下：

```json
{
  "prefix": "622260",
  "bank_name": "交通银行",
  "card_type": "借记卡"
}
```

`prefix` 只能是 6 到 8 位数字；`card_type` 只能为 `借记卡` 或 `信用卡`。服务启动时会校验格式、重复号段和非法卡种，错误数据会阻止服务启动，避免静默误识别。

## 生产更新

不要把完整卡号发送给公网 BIN 查询接口，这会泄露敏感支付数据。应使用已获授权的本地 BIN/IIN 数据源，将其转换为上述 JSON 格式。

将维护后的文件放到：

```text
data/bank_card/catalog.json
```

在 `.env` 设置：

```dotenv
BANK_CARD_CATALOG_FILE=data/bank_card/catalog.json
```

`docker-compose.yml`、`docker-compose.scale.yml` 和 OpenVINO 实验 Compose 均已将 `data/bank_card` 只读挂载到容器。更新数据后重启服务生效：

```powershell
docker compose up -d --force-recreate
```

Linux：

```bash
docker compose up -d --force-recreate
```

## 上线前校验

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -c "from app.config import BANK_CARD_CATALOG_FILE; from app.parsers.bank_card_catalog import BankCardCatalog; BankCardCatalog.load(BANK_CARD_CATALOG_FILE); print('catalog valid')"
```

再执行：

```powershell
.\.venv\Scripts\python.exe test_new_parsers.py
```

完整 BIN/IIN 库更新后，建议至少回归常见国有行、股份制银行、农商行、农村信用社和外资银行的真实脱敏样本。

## 导入公开离线基线

项目提供 `scripts/import_card_bin_db.py`，可导入 `card-bin-db@1.0.2` 包内标记为
`CN` 的 BinCheck 数据。该包标注为 MIT，但其上游数据的商业再分发条款仍应由部署方确认；
它不是银联官方的完整实时库。

```powershell
.\.venv\Scripts\python.exe scripts\import_card_bin_db.py `
  C:\path\to\card-bin-db-1.0.2.tgz `
  app\resources\bank_card\iin_catalog.json
```

导入脚本会展开 6 位范围号段，保留发卡机构英文名和 `DEBIT/CREDIT` 类型码，并生成可由服务启动时校验的 JSON 文件。
