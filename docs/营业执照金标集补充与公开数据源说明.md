## 本次公开数据源检索结果

本次检查了以下方向：

- PaddleOCR 官方仓库及其 OCR、KIE、版面数据集文档
- GitHub 公开仓库搜索
- Hugging Face 数据集元数据搜索
- 公开网页和图片搜索

结论：没有找到能够同时确认以下三项的营业执照专用验证集：

1. 整页营业执照图片
2. 结构化字段金标值
3. 明确的下载和内部评测授权，以及 `train/val/test` 划分

PaddleOCR 官方数据集主要是通用文本检测、文本识别、票据/收据 KIE 和版面分析数据，不是营业执照字段解析集。它们可以帮助验证通用 OCR 能力，但不能直接用于本项目 8 个营业执照字段的准确率报告。

因此本次没有把搜索到的网页图片下载进正式金标目录。图片搜索命中的多批结果实际是“营业中/休息中”门店标牌、图标、风景图或宣传素材，不属于营业执照，已全部清理。

## 为什么没有直接下载网上图片

营业执照包含统一社会信用代码、企业名称、地址和经营范围等企业信息。网页图片即使可以访问，也不代表允许下载、保存、再分发或用于模型评测。没有明确许可证、数据集协议或权利人授权的图片，不应直接进入正式金标集。

搜索公开数据时还要区分：

- **检测数据集**：通常只有文本框，适合验证文字检测，不足以验证结构化字段。
- **识别数据集**：通常只有裁剪文字和文本标签，适合验证文字识别，不包含营业执照字段关系。
- **文档 OCR 数据集**：可能包含整页图像和 JSON/XML 标注，才适合改造成字段金标。
- **结构化营业执照金标集**：必须同时有图片、字段值和明确授权，最适合本项目。

目前未找到可以直接确认“图片、字段值、授权协议”三项都满足的公开营业执照字段金标集，因此没有自动下载外部数据。

## 推荐补充方式

### 方式一：内部授权收集

优先从业务实际收到的样本中收集，并取得公司内部使用授权。每种版面族至少收集 3-5 张，拍摄条件覆盖：

- 正本和副本
- 平拍、轻微旋转、透视和反光
- 红章覆盖统一社会信用代码、名称或地址
- 清晰扫描件和手机拍摄件
- 横向、纵向和不同分辨率

### 方式二：公开数据集二次使用

只有在数据集页面明确给出许可证或研究使用条款时才使用。下载前记录：

1. 数据集名称和版本
2. 来源 URL
3. 许可证或授权条款
4. 下载日期和文件 SHA-256
5. 是否允许内部评测、修改和再分发

不满足以上信息的图片只能临时人工查看，不能复制到正式金标目录。

### 方式三：合成版面回归

项目已经增加 10 类版面族的合成 OCR 行回归测试，用于验证解析规则和字段边界。合成数据不能代替真实准确率报告，但适合在每次修改代码后快速发现回归。

其中：

- `copy_type`：正本、副本、无法确认
- 无法从图片确认的字段留空，并在 `notes` 说明

## 验证顺序

新增图片后按以下顺序执行：

1. 先人工填写 `final_*` 金标字段
2. `review_status=corrected`，填写 `reviewer` 和 `reviewed_at`
3. 运行营业执照准确率评估脚本
4. 查看字段级准确率和具体图片失败清单
5. 修改解析器后重新跑完整集
6. 只有在真实金标集和合成回归都通过后，才扩大生产规则
