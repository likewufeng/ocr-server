# 无外网与内网环境部署

本文适用于生产服务器网络较差、不能访问 Docker Hub/PyPI，或完全没有外网的情况。
推荐在一台有外网的构建机上完成镜像构建和依赖下载，再把完整离线包传入服务器。
不要在离线服务器上执行 `docker compose ... --build`，因为 Dockerfile 构建期间需要
访问 Debian 软件源和 PyPI。

以下命令以当前双实例 CPU 生产配置 `docker-compose.scale.yml` 为准，对外端口由
`.env` 中的 `OCR_HOST_PORT` 控制。

## 一、部署前提

- 构建机已安装 Docker，且能够访问 Docker Hub、Debian 软件源和 PyPI。
- 目标服务器已离线安装 Docker Engine 和 Docker Compose V2 插件。
- 构建机与服务器 CPU 架构必须一致。常见 x86_64 服务器使用 `linux/amd64`；ARM
  服务器使用 `linux/arm64`，不能直接混用镜像。
- 服务器至少预留 10 GB 可用磁盘空间，实际空间以导出的镜像和运行数据量为准。
- 完整离线包必须包含 OCR 镜像、Nginx 镜像、`.env`、Compose 文件、Nginx 配置和
  `models` 目录。

如果服务器尚未安装 Docker，应在同发行版、同版本、同 CPU 架构的联网 Linux
环境中准备 Docker Engine、containerd、Buildx 和 Compose 插件的全部离线安装包，
或使用公司内网软件源安装。只安装 Docker 客户端不能运行本服务。安装后确认：

```bash
docker version
docker compose version
```

## 二、在有网构建机制作离线包

在项目根目录使用 PowerShell 执行。下面以 x86_64 Linux 服务器为例：

```powershell
$Version = Get-Date -Format "yyyyMMdd-HHmm"
$BundleName = "ocr-server-$Version-linux-amd64"
$BundleDir = "release\$BundleName"

New-Item -ItemType Directory -Force "$BundleDir\deploy\nginx" | Out-Null

# 构建带版本号的 Linux 生产镜像。
docker build --platform linux/amd64 -t "ocr-server:$Version" .

# Nginx 也必须提前下载，离线服务器无法从 Docker Hub 拉取。
docker pull --platform linux/amd64 nginx:1.27-alpine

# 一个 tar 中同时保存两个镜像。
docker save -o "$BundleDir\docker-images.tar" `
  "ocr-server:$Version" nginx:1.27-alpine

Copy-Item docker-compose.scale.yml "$BundleDir\"
Copy-Item .env "$BundleDir\"
Copy-Item deploy\nginx\ocr.conf "$BundleDir\deploy\nginx\"
Copy-Item models "$BundleDir\models" -Recurse
Set-Content -Encoding ASCII "$BundleDir\VERSION" $Version

# 打成一个便于传输的压缩包。
tar -czf "release\$BundleName.tar.gz" -C release $BundleName
Get-FileHash "release\$BundleName.tar.gz" -Algorithm SHA256
```

记录最后输出的 SHA-256。若目标服务器是 ARM，将命令中的 `linux/amd64` 改为
`linux/arm64`，并在实际 ARM 环境或支持该平台的 Buildx 构建器上构建。

`models` 目录目前约 0.31 GB。它虽然也可能有部分内容存在于构建上下文中，但生产
Compose 会把宿主机 `models` 挂载到容器内并覆盖镜像中的同名目录，因此必须单独
放进离线包。建议复制整个目录，不要只挑当前 mobile 模型，否则以后切换模型配置时
可能再次触发联网下载。

## 三、传输并校验

把 `release/ocr-server-<版本>-linux-amd64.tar.gz` 传到服务器，例如放到
`/opt/packages`。网络不稳定时优先使用支持断点续传的 `rsync --partial`、SFTP 客户端
或内网文件服务器。

在服务器计算校验值，并与构建机记录的 SHA-256 对比：

```bash
sha256sum /opt/packages/ocr-server-<版本>-linux-amd64.tar.gz
```

校验不一致时不要继续导入，重新续传或重新复制文件。

## 四、在离线服务器安装

```bash
sudo mkdir -p /opt/ocr-server/releases
sudo tar -xzf /opt/packages/ocr-server-<版本>-linux-amd64.tar.gz \
  -C /opt/ocr-server/releases
cd /opt/ocr-server/releases/ocr-server-<版本>-linux-amd64

# 所有版本共用固定动态数据目录，升级或回滚不会丢失上传、输出、缓存和日志。
sudo mkdir -p /opt/ocr-server/data/{uploads,outputs,cache,logs/ocr-1,logs/ocr-2}
sudo ln -s /opt/ocr-server/data data

# 导入 OCR 和 Nginx 镜像，全程不访问外网。
sudo docker load -i docker-images.tar

# Compose 固定使用 ocr-server:production，将本次版本指向生产标签。
VERSION=$(cat VERSION)
sudo docker tag "ocr-server:${VERSION}" ocr-server:production

# 确认两个镜像均已存在。
sudo docker image inspect ocr-server:production nginx:1.27-alpine >/dev/null

# 检查配置。按服务器端口和 CPU 核数修改 .env 后再启动。
sudo docker compose -f docker-compose.scale.yml config
sudo docker compose -f docker-compose.scale.yml up -d --no-build --pull never
```

`--no-build` 禁止在服务器重新构建，`--pull never` 禁止连接外部镜像仓库。启动时
两个 OCR 实例需要加载模型，首次健康检查可能需要几分钟。

查看状态和日志：

```bash
sudo docker compose -f docker-compose.scale.yml ps
sudo docker compose -f docker-compose.scale.yml logs -f --tail=200
```

默认端口的健康检查和接口文档：

```bash
curl -f http://127.0.0.1:18081/health
curl -f -o /dev/null http://127.0.0.1:18081/docs
```

健康接口应返回 HTTP 200，且包含 `"model_ready":true`。如果修改了
`OCR_HOST_PORT`，将命令中的 `18081` 替换为实际端口。

## 五、通过内网镜像仓库部署

如果公司有 Harbor 或其他内网 Docker Registry，可以只通过内网仓库分发镜像，
但 `models`、`.env`、Compose 和 Nginx 配置仍需通过代码发布包或内网文件服务分发。

在有网构建机完成镜像构建后，将镜像推到内网仓库：

```bash
docker tag ocr-server:<版本> registry.intranet/ocr/ocr-server:<版本>
docker tag nginx:1.27-alpine registry.intranet/base/nginx:1.27-alpine
docker push registry.intranet/ocr/ocr-server:<版本>
docker push registry.intranet/base/nginx:1.27-alpine
```

在生产服务器从内网仓库拉取，然后添加 Compose 当前使用的本地标签：

```bash
docker pull registry.intranet/ocr/ocr-server:<版本>
docker pull registry.intranet/base/nginx:1.27-alpine
docker tag registry.intranet/ocr/ocr-server:<版本> ocr-server:production
docker tag registry.intranet/base/nginx:1.27-alpine nginx:1.27-alpine
docker compose -f docker-compose.scale.yml up -d --no-build --pull never
```

生产服务器只需要访问内网 Registry，不需要访问 Docker Hub、PyPI 或 Debian 软件源。

## 六、升级和回滚

每次发布都使用新的版本号，不要覆盖旧的版本镜像和发布目录。升级步骤：

```bash
docker load -i docker-images.tar
VERSION=$(cat VERSION)
docker tag "ocr-server:${VERSION}" ocr-server:production
ln -sfn /opt/ocr-server/data data
docker compose -f docker-compose.scale.yml up -d --no-build --pull never --force-recreate
curl -f http://127.0.0.1:18081/health
```

升级失败时，把生产标签重新指向上一个已验证版本，再重建容器：

```bash
docker tag ocr-server:<上一个版本> ocr-server:production
docker compose -f docker-compose.scale.yml up -d --no-build --pull never --force-recreate
```

上述安装流程已将每个版本的 `data` 软链接到 `/opt/ocr-server/data`。发布、升级和
回滚时不要删除这个共享目录；程序会按照 `.env` 中的保留周期自动清理其中的动态
文件和日志。

## 七、常见问题

- 出现 `pull access denied` 或尝试连接 Docker Hub：镜像未正确导入或标签不匹配，
  检查 `docker image ls`，并确保启动命令带 `--pull never`。
- 启动日志显示正在下载模型：离线包遗漏了模型文件，或 `models` 目录层级不正确。
  Compose 文件旁应直接存在 `models/official_models` 等目录。
- 出现 `exec format error`：构建镜像与服务器 CPU 架构不一致。
- 容器一直不健康：先检查 `docker compose ... logs ocr-1 ocr-2`，确认模型文件完整、
  内存充足，并检查 `.env` 中的模型和设备配置。
- 端口无法访问：检查 `.env` 的 `OCR_HOST_PORT`、服务器防火墙和安全组。双实例的
  `8001/8002` 只绑定到服务器本机，外部调用应使用 `OCR_HOST_PORT`。
