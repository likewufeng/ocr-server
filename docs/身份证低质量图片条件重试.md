# 身份证低质量图片条件重试

## 默认配置

```dotenv
OCR_ID_FRONT_QUALITY_RETRY_ENABLED=true
OCR_ID_FRONT_RETRY_ON_INCOMPLETE=true
OCR_ID_FRONT_RETRY_SCALE=1.5
OCR_ID_FRONT_RETRY_MAX_SIDE=2400
OCR_ID_FRONT_RETRY_BLUR_THRESHOLD=45
OCR_ID_FRONT_RETRY_MIN_SIDE=700
OCR_ID_FRONT_RETRY_DARK_MEAN=35
OCR_ID_FRONT_RETRY_BRIGHT_MEAN=235
OCR_ID_FRONT_RETRY_CLIPPED_RATIO=0.08
```

## 处理规则

仅身份证正面参与条件重试。首轮结果完整时不增加推理；首轮出现模糊、分辨率偏低、过暗、过亮、明显裁剪，或关键字段证据不完整时，才执行一次温和增强：放大、CLAHE 和轻度锐化。

系统比较首轮与重试结果的姓名、性别、民族、生日、地址、身份证号证据。只有重试结果更完整才采用，否则保留首轮结果。重试结果的坐标会自动映射回原图坐标，接口格式不变。

`OCR_ID_FRONT_USE_DOC_UNWARPING` 仍建议保持 `false`。条件重试与 UVDoc 是两套独立机制，当前不自动组合，避免再次引入身份证版面坐标偏移。

## 排查文件

请求启用 `OCR_SAVE_PREPROCESSED_IMAGE=true` 时，`data/outputs/{request_id}/` 中可能出现：

- `quality_info.json`：质量指标、触发原因、是否重试、最终选用首轮还是重试。
- `preprocessed_id_front_retry.jpg`：实际用于二次识别的增强图片。

动态文件仍按项目现有清理策略自动过期。重试会增加命中低质量条件请求的响应时间，不能恢复已经被遮挡、严重过曝或完全模糊的文字。

## 关闭方式

```dotenv
OCR_ID_FRONT_QUALITY_RETRY_ENABLED=false
```

修改 `.env` 后需要重启 `python start.py`；Docker 需要重新创建容器。代码已将缓存版本默认提升到 `5`，会隔离旧 OCR 缓存。
