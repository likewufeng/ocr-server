# OCR 金标数据集使用指南

## 目的与边界

金标数据集用于验证当前 OCR 接口的结构化识别准确率，不能提交到 Git、网盘或公开文件系统。身份证图片和 `annotation_template.csv` 都含敏感信息，应限制访问权限并使用受控备份。

当前身份证正面数据集路径：

```text
D:\web\self\study\ocr-datasets\id-front\v1_20260807
```

已核对该版本包含 400 张图片、400 条标注，所有 `image_file` 均能找到对应图片；标注状态为 304 条 `confirmed` 和 96 条 `corrected`。

## 推荐结构

每个版本独立且一经发布即冻结：

```text
ocr-datasets/
  id-front/
    v1_20260807/
      images/
      annotation_template.csv
      selection_manifest.json
      README.md
      reports/
        api_regression_20260807-160818.json
        api_regression_20260807-160818.md
        baseline_accuracy_report.json
        baseline_accuracy_report.md
```

- `images/`：只放该版本对应的原始图片副本，文件名不得包含姓名、身份证号等字段。
- `annotation_template.csv`：人工金标。`final_*` 是唯一用于准确率比较的字段；`pre_*` 仅保留当时的 OCR 预标注，便于分析错误。
- `selection_manifest.json`：记录抽样来源、随机种子及图片清单，用于复现样本选择。
- `reports/`：只放无原文内容的统计报告。
- `README.md`：记录数据来源、抽样规则、标注规则、创建人和版本说明，不记录证件字段原文。

当前版本的统计与诊断报告统一放在 `reports/`；后续新报告也必须输出到该目录。

## 标注规则

`review_status` 只能使用以下值：

- `confirmed`：预标注正确，`final_*` 填入确认后的字段值。
- `corrected`：预标注有误，`final_*` 填入人工确认后的字段值。
- `unreadable`：原图无法可靠判读，不计入准确率分母；在 `notes` 中记录原因。

不要使用空白表示“尚未校对”。未完成校对的行应保持空状态，统计脚本会将其排除并单独计数。

对于被遮挡、原图不存在、无法确认的字段，保留空值并在 `notes` 说明。不要依据身份证号推断出生日期后再写入金标，金标应以人工可从图片确认的内容为准。

## 版本管理

当前 `v1_20260807` 已参与身份证生日解析优化，因此它是开发回归集，不宜作为唯一的发布验收集。

1. 在本版本完成核对并生成正式报告后，冻结版本，不再直接改动图片和 `final_*`。
2. 后续发现标注错误时，复制为新版本，例如 `v2_20260815`，在新版本修正并重新生成报告。
3. 后续额外抽取 200 至 400 张未参与规则设计的图片，建立 `holdout_v1_202608xx`，仅在发布前或模型切换时运行。
4. 未来若训练模型，训练集、开发回归集和发布验收集必须物理分开，同一图片不得跨集合出现。

## 运行接口回归

先启动本地服务并确认健康检查：

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:8000/health
```

在项目根目录执行以下 PowerShell 命令。报告只含统计数，不包含图片或证件字段原文：

```powershell
$dataset = 'D:\web\self\study\ocr-datasets\id-front\v1_20260807'
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$reports = Join-Path $dataset 'reports'
New-Item -ItemType Directory -Force $reports | Out-Null

& .\.venv\Scripts\python.exe scripts\evaluate_id_front_review_set.py `
  --input-csv "$dataset\annotation_template.csv" `
  --images-dir "$dataset\images" `
  --url 'http://127.0.0.1:8000' `
  --timeout 120 `
  --output-json "$reports\api_regression_$stamp.json" `
  --output-markdown "$reports\api_regression_$stamp.md"
```

接口改动、模型切换、Paddle/PaddleX 依赖升级、预处理策略调整后都应执行一次。若请求失败数不为 0，先排查失败原因，不能只看成功样本的准确率。

## 解读与发布判断

优先查看以下指标：

- `all_fields_exact_rate`：一张证件的全部字段均正确才计为正确，作为主要发布指标。
- `field_accuracy`：定位姓名、生日、地址等具体字段的回归。
- `failed_requests`：必须为 0；否则报告不能作为完整回归结论。

推荐发布要求：验收集全字段准确率不得低于当前已批准基线，关键字段不得回归，并且请求失败数为 0。任何指标下降都应保留新旧报告并定位差异样本后再决定是否发布。

## 鲁棒性增强集

不要直接修改 `v1_20260807/images`。基于它生成的模糊、透视、低分辨率等图片应放在独立目录：

```text
D:\web\self\study\ocr-datasets\id-front-robustness\v1_20260807-r1
```

生成器采用固定随机种子，同一源图片和场景每次都会得到相同的变体。默认的 `scored` 场景包括高斯模糊、运动模糊、低分辨率、噪点、旋转、透视、轻微比例扭曲、明暗异常、JPEG 压缩和复杂背景。这些场景仍完整保留证件信息，因此可与原始金标逐字段比较。

强反光、阴影、边缘缺失、内容遮挡、屏幕翻拍使用 `diagnostic` 标记。它们会生成并统计接口输出，但不纳入总分，因为图片可能被刻意遮住字段；屏幕翻拍是否合格还需要接口提供专门的风险标记字段后才能自动判定。

生成全部场景：

```powershell
$source = 'D:\web\self\study\ocr-datasets\id-front\v1_20260807'
$robustness = 'D:\web\self\study\ocr-datasets\id-front-robustness\v1_20260807-r1'

& .\.venv\Scripts\python.exe scripts\generate_id_front_robustness_set.py `
  --source-dir $source `
  --output-dir $robustness `
  --seed 20260807 `
  --include-diagnostic
```

运行接口回归，建议先使用 `--concurrency 1`，避免压测行为影响鲁棒性结论：

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
New-Item -ItemType Directory -Force "$robustness\reports" | Out-Null

& .\.venv\Scripts\python.exe scripts\evaluate_id_front_robustness_set.py `
  --source-csv "$source\annotation_template.csv" `
  --images-dir "$robustness\images" `
  --manifest "$robustness\manifest.csv" `
  --url 'http://127.0.0.1:8000' `
  --concurrency 1 `
  --output-json "$robustness\reports\robustness_$stamp.json" `
  --output-markdown "$robustness\reports\robustness_$stamp.md"
```

报告按场景分别列出全字段正确率，并同时保留英文场景标识。英文标识就是生成图片文件名中双下划线后的部分，例如 `0004__motion_blur.jpg` 对应“运动模糊”。发布判断以 `scored_overall` 和每个 `scored` 场景为准，诊断场景用于暴露边界条件和规划风险检测能力。

| 英文标识 | 中文名称 | 含义 |
| --- | --- | --- |
| `gaussian_blur` | 失焦模糊 | 对焦不准造成整体模糊 |
| `motion_blur` | 运动模糊 | 手抖或证件移动造成拖影 |
| `low_resolution` | 低分辨率 | 图片像素过低或被大幅缩小 |
| `gaussian_noise` | 画面噪点 | 暗光高感光度产生噪点 |
| `rotation` | 图片倾斜 | 证件未摆正或拍摄角度倾斜 |
| `perspective` | 透视畸变 | 斜角拍摄造成梯形变形 |
| `aspect_warp` | 轻微比例扭曲 | 证件长宽比例发生变化 |
| `illumination` | 整体过亮或过暗 | 曝光或光照异常 |
| `jpeg_compression` | 高压缩失真 | JPEG 压缩导致细节损失 |
| `background` | 复杂背景 | 证件位于杂乱或非纯色背景 |
| `glare` | 局部强反光 | 反光覆盖局部文字 |
| `shadow` | 局部阴影 | 局部光照不足形成暗部 |
| `edge_crop` | 边缘缺失 | 拍摄不全导致证件边缘被裁掉 |
| `occlusion` | 内容遮挡 | 手指或物体遮住局部信息 |
| `screen_rephoto` | 屏幕翻拍 | 对屏幕上的证件图片再次拍摄 |

## 安全与备份

- 仅授权的标注和研发人员可访问数据目录。
- 使用加密磁盘或受控文件服务器保存，备份同样应加密。
- 禁止把图片、CSV、含字段原文的错误明细上传到代码仓库、工单、即时通信群或公共对象存储。
- 报告、日志和截图对外发送前，确认其中没有姓名、地址、身份证号和原图。
