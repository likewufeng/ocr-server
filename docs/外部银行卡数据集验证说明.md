# 外部银行卡数据集验证说明

## 数据集位置

以下原始数据集由调用方手动下载，项目中的评测脚本只读取，不复制、不移动、不修改其中的图片：

```text
D:\web\self\study\dataset\CreditCard-OCR
D:\web\self\study\dataset\CardNumber-DeepOCR
```

## 数据集适用范围

### CreditCard-OCR

- 数据划分：训练集 1,341 张，验证集 123 张，测试集 60 张。
- 标注格式：YOLO 区域框，类别为卡号、有效期、银联标志等视觉区域。
- 可用于：后续增加银行卡卡号区、有效期区、标志区的检测能力时，评估区域定位效果。
- 不可用于：当前结构化 `/ocr` 接口的卡号、银行名称、卡类型、有效期文本准确率评测，因为 YOLO 标签没有这些字段的文本金标。
- 授权注意：下载目录未发现 `LICENSE` 文件。在把图片纳入项目数据集、训练或对外发布前，需要由数据集使用方确认来源和许可范围。

### CardNumber-DeepOCR

- 许可证：MIT。
- 可用测试图片：`test_synthesized` 中 20 张、`test_real` 中 4 张，文件名为 16 位数字卡号。
- 可用于：验证裁剪卡号区域的数字串识别。
- 不可用于：验证完整卡面、中英文银行名称、卡类型、有效期及持卡人姓名。
- 场景限制：样本主要是伊朗银行卡裁剪卡号区域，不能代表中国银行卡的全卡面识别效果。

## 执行卡号回归

本地服务运行在 `http://127.0.0.1:8000` 后执行：

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_bank_card_number_source_set.py `
  --source-root 'D:\web\self\study\dataset\CardNumber-DeepOCR\Datasets' `
  --output-dir 'D:\web\self\study\ocr-datasets\bank-card\external-card-number-v1\reports'
```

脚本请求 `/ocr?document_type=bank_card&auto_orientation=false`，输出 CSV 明细和 Markdown 报告。原始图片不会进入项目目录或 Git。

## 指标口径

生产银行卡解析器会使用 Luhn 校验过滤无效卡号，避免将 OCR 误读返回给调用方。由于该公开数据集中的部分合成号码本身不通过 Luhn 校验，报告同时给出两种结果：

- `Luhn 合法样本完全正确率`：生产接口可参考的卡号字段准确率。
- `全部样本完全正确率`：包含无效合成号，只用于排查 OCR 数字识别能力，不能作为当前 API 的验收指标。

真正的银行卡接口验收，仍应以具有授权的中国完整银行卡金标集为准；卡号、持卡人姓名和有效期应脱敏或使用合成值。
