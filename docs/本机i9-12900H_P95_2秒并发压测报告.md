# 本机 i9-12900H / RTX 3060 P95 2 秒并发压测报告

报告日期：2026-08-06

## 1. 结论

在本次真实混合文档负载下，当前本机**不存在可以承诺 `P95 <= 2s` 的正整数并发值**。原因是最终的单并发 120 次复测中，整体 P95 为 **2.877s**，其中营业执照 P95 为 **2.928s**；即使没有排队，仍有超过 5% 的请求超过 2 秒。

因此，针对“身份证正反面 + 高分辨率营业执照”的当前混合比例：

| SLA | 可承诺最大 HTTP 并发 | 说明 |
| --- | ---: | --- |
| P95 <= 2s | 无 | 单并发已不满足，不能以 1、2 或更高并发对外承诺。 |
| 仅作短时试运行 | 1 | 可处理请求，但 P95 不达标，不能作为 2 秒 SLA 容量。 |

此前 2 并发、60 次的 P95 曾为 1.487s，但 120 次复测升至 2.369s。短样本遗漏了营业执照的慢请求，不能用于容量承诺。

## 2. 测试环境

| 项目 | 配置 |
| --- | --- |
| 操作系统 | Windows 11 专业版 |
| CPU | Intel Core i9-12900H（14 核 20 线程） |
| 内存 | 32 GB，4800 MT/s |
| GPU | NVIDIA GeForce RTX 3060 Laptop GPU，6 GB 显存 |
| NVIDIA 驱动 | 546.30 |
| 服务启动方式 | 本机 `python start.py`，接口 `http://127.0.0.1:8000` |
| OCR 模型 | PP-OCRv6 `medium` |
| 推理设备 | `gpu:0`，Paddle Dynamic |
| OCR 并发槽 | `OCR_MAX_CONCURRENT_REQUESTS=1` |
| 文本识别批量 | `OCR_TEXT_RECOGNITION_BATCH_SIZE=6` |
| 自动方向 | 开启（默认生产行为） |
| 缓存 | 每次请求内容均扰动，420 次均为缓存未命中 |

压测结束后的 GPU 状态为显存使用约 5.9 GB / 6 GB、温度 85 C。该显存余量不足以通过简单增大识别批量或在同一进程中增加更多 GPU 推理并发来解决 SLA 问题。

## 3. 测试方法

- 使用本机回环地址调用真实 `/ocr` HTTP 接口，包含上传、原文件保存、预处理结果保存、OCR 推理、解析和响应序列化。
- 样本为已留存的三类真实文档各一张：身份证正面 PNG（约 285 KB）、身份证反面 JPG（约 133 KB）、高分辨率营业执照 JPG（约 2.5 MB）。
- 请求按“身份证正面、身份证反面、营业执照”循环发出，文档类型通过 `document_type` 显式指定。
- 每个请求追加无意义尾部字节，使图片解码结果不变、缓存键不同，避免命中 OCR 缓存。
- 以下是短预热/探测与长复测。P95 为最近秩（nearest-rank）计算，失败率为 HTTP 或业务失败占比。

该结果代表本地回环网络下的服务端能力；真实部署时的公网/内网上传时间、磁盘性能、其他进程争抢和更多样本差异只会增加波动。

## 5. 容量解释

这里的“并发”是同时在途的 HTTP 请求数，不等同于推理并行数。当前配置 `OCR_MAX_CONCURRENT_REQUESTS=1`，每个进程同一时刻只执行一个 OCR 推理，其余请求会在进程内排队。

因此：

- 将该参数直接从 1 改为 2 或更大，不是可靠扩容手段。当前 GPU 显存已经接近满载，且现有实测已显示 2、3 个 HTTP 并发的 P95 超标。
- 多开同型号 `medium` GPU 实例同样不可行，因为单个服务已占用约 5.9 GB 显存。
- 120 次不是 30 分钟以上的正式稳定性压测，但足以否定“当前混合负载可承诺 P95 2 秒”的结论。要做采购或上线承诺，仍应在目标环境用更多不同营业执照、发票和手机拍摄照片进行 30-60 分钟压测。

## 6. 达到 2 秒 SLA 的建议

要使整体混合负载达到 P95 2 秒，优先按以下顺序处理：

1. **文档分级路由**：身份证继续使用当前高精度模型；营业执照单独配置更快的模型或单独 SLA。不能把身份证的快速结果外推到营业执照。
2. **针对营业执照做模型基准**：用同一批样本比较 PP-OCRv6 `small` / `tiny` 和 `medium` 的字段准确率与 P95。只有准确率验收通过时，才可用较小模型换取延迟。
3. **增加 GPU 显存后再做并行实验**：16 GB 及以上显存的 GPU 才有空间测试更大的识别批次或多个推理槽；必须以实测为准，不能只按显存容量线性估算。
4. **将慢文档异步化或拆分 SLA**：若营业执照允许 3-5 秒或异步返回，可将其与身份证的 2 秒实时 SLA 分开，成本和实现风险更可控。
5. **减少非必要落盘开销仅作为辅助**：生产排查需要保存原图和预处理图，不能为了压测直接关闭。可以改为仅保存失败、低置信度和抽样请求，再重新测量收益。

在上述调整完成并通过同等样本的长压测之前，不建议对调用方宣称本机可承诺任何正整数并发下的混合文档 `P95 <= 2s`。
